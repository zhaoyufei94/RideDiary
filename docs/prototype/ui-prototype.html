01 / A DAILY RITUAL

记录一趟，读懂日常

第一版是一款手机独立运行的安卓 App。手动开始记录，自动识别通勤路线与到达；需要看进度时打开页面，日常记录支持熄屏设计。

01 / 出发

轻点开始记录

先记录位置和时间，再逐步判断是不是熟悉的通勤路线，不漏掉刚出门的一段。

02 / 途中

知道自己走到了哪

沿路线的距离计算进度，小摩托车陪你前行。已耗时、等待和预计到达集中展示。

03 / 到达

给今天一个解释

到达终点范围并稳定停留后结束通勤，拆分移动与等待，和同路线近期记录比较。

04 / 回看

把一趟变成习惯

按月回看天数、里程和时间；从某次行程创建路线，上下班与不同走法分别管理。

02 / FEELING VS. FACT

感觉更堵，也可能更快

总耗时只是答案，移动和等待才是原因。对比采用同方向、同路线的近期记录，避免把两条不同走法放在一起。

今天 vs. 平常

示例：近 20 次上班路线，按移动与等待分别取中位数

分项历史基准31 分 48 秒

慢在路上，快在少等。

今天移动时间 23:18，比移动历史基准多 1 分钟；静止等待 06:18，比等待历史基准少 3 分 12 秒。两项合计，反而少用了 2 分 12 秒。

＝ 总计 −02:12

分项中位数之和不一定等于总耗时中位数。App 的总用时排名、均值与中位数会按完整行程另算。

分布 / DEPARTURE

几点出发更从容？

将出发时间与通勤耗时放在一起观察。数据足够后，按时段看分布和波动，不把偶然一次当作规律。

路段 / WAITING

时间都等在哪里？

轨迹对应停车片段，找出反复停留的位置。标记路口后可看路口停留估计，堵车和临停仍可能混在其中。

月份 / ROUTINE

这个月骑了多少？

统计通勤天数、单程次数、总里程、移动与静止时间。单日一趟也算一个通勤日，不把往返当成两天。

03 / CLEAR DEFINITIONS

让每个数字都有口径

统计默认排除已手动标记的异常行程；原始记录保留。历史不足时显示“学习中”，不伪装成准确预测。

指标计算与展示边界处理
通勤识别起终点范围、行进方向与轨迹重合程度；时间段作为辅助。上班 / 下班分开。偏离路线标记异常，可在 App 修正。
出发 / 到达平均、最早、最晚时间；到达采用终点范围与稳定停留判断。跨午夜按出发日归档，时间先相对所属通勤时段展开再求均值；支持手动修正起止点。
通勤用时总耗时、平均 / 最快 / 最慢、中位数，以及历史差值。总耗时包含途中等待。异常长时间临停可标记后排除。
静止等待低速阈值、持续时间和定位质量共同识别；每趟累计的平均 / 最短 / 最长。不直接使用速度等于零，不等同于红灯时间；定位失效片段单列未知。
平均速度全程均速 = 有效里程 ÷ 总耗时；移动均速单独记录。过滤明显漂移；定位缺失较多时提示数据不完整。
进度 / 预计到达沿已选路线的完成距离占比；剩余路段历史耗时估算到达。绕路时降低确定性，历史不足显示范围或学习中；不依赖实时路况 API。
月度汇总通勤天数、单程次数、总里程、总用时、静止占比。按本地日期和出发日统计，同日往返计 1 天、2 次。
04 / PHONE FIRST

一部手机，就可以开始

定位、记录、识别、统计和展示都留在手机。不需要额外硬件，也不以信号灯数据或付费地图接口作为前提。
