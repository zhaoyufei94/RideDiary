# 途记 / RideDiary

每天的骑行，多一点了解。

手机独立运行的原生安卓通勤记录 App：手动开始、系统定位前台服务、Room 本地保存、路线识别、静止分析、到达小结、历史与月度统计。不需要 GMS、地图 Key、账号、服务器或埋点，不上传轨迹，不申请联网权限。[English](README.md)。

界面保留[交接原型](docs/prototype/ui-prototype.html)的米白、森林绿、沙色与矢量摩托车进度条，四个页面使用 Jetpack Compose。默认中文，右上角切换英文，单一语言设置保存在私有 SharedPreferences 中。

## 环境、构建与安装

固定版本：JDK 17、Gradle 8.11.1、AGP 8.9.2、Kotlin / Compose 编译插件 2.1.20、KSP 2.1.20-1.0.32、compile/target SDK 35、Build Tools 35.0.0、最低 Android 8 / API 26；Room 2.7.1、Compose BOM 2025.04.01。采用已知兼容组合，不宣称是最新 SDK。

安装 Android Studio 或 Android 命令行 SDK，将 `JAVA_HOME` 指向 JDK 17，`ANDROID_HOME` 指向 SDK；也可在不提交的 `local.properties` 中配置 `sdk.dir=/绝对路径/sdk`。安装 `platforms;android-35`、`build-tools;35.0.0`、`platform-tools`；阅读并接受对应 SDK 许可。macOS 的 `/usr/bin/java` 可能只是空桩，不等于已经安装 JDK。

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
python3 scripts/check-resources.py
adb install -r app/build/outputs/apk/debug/app-debug.apk
# 连接 Android 8+ 手机或模拟器后：
./gradlew :app:connectedDebugAndroidTest
```

当前工作目录已经在 `.tooling/` 准备了不提交的本地 JDK/SDK/缓存。可直接运行 `./scripts/gradle-local.sh` 使用这些工具，不修改系统安装；也可传入指定 Gradle 任务。在其他机器上仍需按上文配置 JDK/SDK，该脚本不会自动下载或接受许可。

如果 PATH 中没有 `adb`，连接并在手机上授权后，本机可用 `.tooling/android-sdk/platform-tools/adb install -r app/build/outputs/apk/debug/app-debug.apk` 安装。

Debug APK 使用开发签名。未生成正式发布密钥，也未替用户选择开源许可证。本机工具 `.tooling/` 与 `local.properties` 不进入 Git。

## 体验回放与真实记录

在通勤页选择“体验轨迹回放”，可以查看六趟合成历史与路线。点击播放后约 11 秒跑完一趟确定性轨迹，可暂停/继续，观察沿有序路线移动的小摩托车，以及到达小结、历史、路线和月度筛选。回放只在内存，不写入真实数据库。退出演示返回真实记录；真实记录期间不能进入演示。

真实骑行请停车后点击“开始记录”，阅读说明并授予精确定位。Android 13+ 按需请求通知；拒绝通知仍可记录，但需要回到 App 结束，或使用系统任务管理器。仅近似位置或拒绝位置权限会阻止开始；初次浏览和演示无需权限。系统定位关闭时给出提示。定位前台服务提供持续通知及结束入口，目标支持后台与熄屏记录。不申请全天后台位置，无开机启动或自动开始。

首次骑行手动结束后，在“小结”打开行程，点击“设为通勤路线”，命名、选择上班/下班，确认起终点半径（20–500 米）。需要至少四个有效点和 150 米轨迹。此后仍手动开始，App 根据实际轨迹识别路线。同方向可有多条路线；平行候选过于接近时维持不确定。沿路线接近终点、进入终点范围并有 30 秒连续新鲜低速定位才确认到达；始终提供手动结束。

详情支持修正路线/方向、标记异常临停或绕路并排除，或按相对原始开始的秒数调整通勤边界。原始点完整保留，统计随修正重新计算。中断的行程显示未知缺口，不计入有效通勤统计，也不会自动重启或悄悄改成正常完成。

## 已实现内容

- 四个可滚动原生页面、空状态、本地轨迹 Canvas、语义标签、中英文资源。
- 服务串行处理记录、重复开始防护、系统 GNSS/网络定位、两秒持久化检查点；UTC、时区、单调间隔、原始点质量及算法版本。
- 移动/静止/未知分段、低速持续确认与候选区间回溯、滞回、精度/过期/跳点/缺口过滤。
- 局部有序路线投影、保守歧义处理、偏离/掉头提示、终点停留确认。
- 最近 20 次此前有效同路线同方向基准；独立总中位数和分项中位数，同位置差异，历史剩余时间中位数及四分位 ETA（至少 3 次）。
- 按出发本地月份、路线和方向联动筛选；通勤日期去重、每趟时间堆叠图、里程/时间/静止汇总，出发与到达平均/最早/最晚，总用时和每趟等待平均/最短/最长、总中位数，跨午夜展开。
- Room 事务、原始点保留、中断恢复提示、通勤边界调整及隔离演示。

## 验证与 OPPO 实测

实际执行结果见[测试记录](docs/testing.zh-CN.md)，计算口径和实现见[设计文档](docs/design.zh-CN.md)。构建通过、合成测试和真实道路效果分开说明。**OPPO 锁屏存活、北京主辅路相邻时的定位表现、到达参数和耗电仍须真机重复通勤验证**，不宣称道路或雨骑认证。

建议上下班各重复数趟，手动记总时间与静止等待；锁屏至少 30 分钟；测试终点前短停、地库/隧道、权限撤回、通知结束、进程终止和重进。记录手机型号、ColorOS/Android 版本与电量。先使用正常电池设置，只在发现中断后针对性测试单个 App 的后台策略，不默认关闭全部省电。请停车后操作。

## 隐私和已知限制

轨迹保存在 App 私有 Room 数据库；关闭系统备份并排除云端和设备迁移备份；不打印精确坐标。这是平台备份策略，不包含 Android 设备存储保护以外的额外加密，部分 OEM 迁移工具仍待验证。卸载或清除存储会丢失本地记录；没有导出、云端找回或版本 1 以后的迁移方案。

GPS 无法可靠区分所有平行道路或车道。算法阈值集中在 `core/Models.kt`，需实测校准。初版不含导航、实时路况、红灯识别、最快纪录引导、付费 API、硬件、地图底图、账号和同步。按常用出发时段优化、等待热点、散点图、导出留待后续。服务没有持有唤醒锁或申请忽略电池优化，熄屏定位节奏与耗电需要 OPPO 实测。当前每次检查点重放当前轨迹、重建派生分段，面向通勤规模，超长记录性能尚待测量。
