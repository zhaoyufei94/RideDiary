# RideDiary / 途记

<img src="docs/brand/ridediary-logo.svg" width="96" height="96" alt="RideDiary 标志" />

**每天的骑行，多一点了解。** · [English](README.md)

当前版本：**0.1.6**。方格纸 Logo 统一用于启动图标、App 页眉、通知与项目展示。

途记是一款离线运行的原生 Android 通勤记录与分析 App。用手机记录每天的骑行，把总耗时拆成移动、静止和未知区间，了解今天的时间花在哪里，再与自己的历史通勤比较。

支持 Android 8.0 及以上版本，面向不同品牌的 Android 手机。无需额外硬件、账号、Google Play 服务或地图 Key。记录和分析均在本机完成，不申请联网权限。

## 能做什么

| 页面 | 主要功能 |
|---|---|
| 通勤 | 手动开始记录，查看耗时、均速、静止时间和定位状态；识别已保存路线后显示摩托车进度条、历史对比及预计到达时间 |
| 小结 | 查看行程历史和到达小结；修正路线、方向、通勤起止边界，排除异常行程；删除行程 |
| 统计 | 先从列表选择路线，再用上班/下班标签查看所选月份的天数、次数、里程、耗时和每趟时间分布 |
| 路线 | 同一名称汇集上班/下班两套实际轨迹；查看各方向样本，编辑或删除整条路线 |

保留米白、森林绿、浅绿和沙色的视觉风格，以及沿路线前进的小摩托车。界面使用 Jetpack Compose / Material 3，默认中文，可在右上角切换英文。

## 记录期间保持亮屏

开始记录后，途记在前台显示时自动保持亮屏，在通勤、小结、统计和路线间切换不受影响。保存或删除本次记录、离开应用后恢复系统休眠；返回正在记录的途记时重新保持亮屏。仍可按电源键手动锁屏，后台记录继续。无需新增权限，亮屏会增加耗电。

## 行程与路线管理

- 长按“小结”中的行程卡片或详情中的小结卡片，选择“删除行程”，确认后删除行程及原始轨迹，统计随之更新；由该行程创建的路线仍保留。
- 从行程详情使用页面返回按钮、系统返回键或返回手势，均回到“小结”列表。
- “路线”页按名称展示列表，每条路线包含上班、下班两个标签及各自轨迹与样本数。长按编辑时名称对两个方向共同生效，端点设置作用于选中的方向。删除整条路线会移除两个方向的参考并解除关联，保留行程及原始轨迹。正在使用的路线需结束记录后再修改。
- 保存行程后自动匹配路线并打开修正列表；日后也可在详情中选择“选择或修正路线”。列表首项为“创建新路线”，也可以选择已有路线和方向。已有路线缺少所选方向时，用本次实际轨迹补充，沿用同一名称。
- 升级后，同名（含末尾上班/下班等方向标签）的旧路线自动归为一条路线，原始行程、方向、参考轨迹和关联保留。统计一次只展示所选路线和方向，没有跨路线总览。
- App 已移除“体验轨迹回放”。合成轨迹仅供自动化测试使用，不打入应用包。

[HTML 原型](docs/prototype/ui-prototype.html)保留为历史视觉参考，其中的演示控件不代表当前 App 功能。

## 权限与运行条件

| 权限或条件 | 何时需要 | 用途与拒绝后的影响 |
|---|---|---|
| 精确位置 | 点击“开始记录”时 | 保存轨迹、分析移动与静止、匹配路线。仅允许近似位置或拒绝定位时，不能开始真实记录；仍可浏览历史 |
| 通知（Android 13+） | 开始真实记录时按需申请 | 提供持续记录通知和结束入口。拒绝后仍可记录，但需回到 App 结束 |
| 系统定位开关 | 真实记录期间 | 关闭时无法取得正常定位，App 会提示，计时继续并把无法判断的区间记为未知 |
| 定位前台服务 | 授权后手动开始记录 | 支持切后台、锁屏后的持续记录；由系统管理，无单独的授权弹窗 |

不申请“始终允许”的后台位置权限，不会开机自启、全天监听或自动开始骑行。记录由用户主动开始。手动停止、通知结束入口和自动到达都先显示“取消／删除／保存”，等待选择时继续记录。

## 怎么使用

1. **记录第一趟**：停车后点击“开始记录”，允许精确位置并打开系统定位。没有已知路线时先显示实际耗时与静止情况。
2. **结束并选择操作**：点击停止，或在收到自动到达提示后选择：**取消**继续记录；**删除**结束并移除本次行程及原始点；**保存**结束并保留行程。通知中的结束入口也打开同一确认框。等待确认期间仍持续定位和计时。
3. **选择或修正路线**：保存时根据完整轨迹尝试匹配已有路线，随后显示路线列表。首项“创建新路线”可命名、选上班/下班和端点范围；也可选已有路线。缺少所选方向时创建该方向的实际参考轨迹。同名反向记录可自动补充为同一条路线的另一方向；多条路线相近时不强行归类。关闭列表仍保留已保存行程及自动结果，可稍后修正。
4. **再次通勤**：仍手动开始。识别需要一定行驶距离，成功后显示摩托车进度条。同一方向参考至少有三次可用历史后，才提供历史对比和预计到达区间。
5. **查看统计**：选月份，从路线列表选择一条路线，再切换上班/下班标签。路线总览汇总所选月份的双向里程、天数和次数，下方图表与耗时再按方向筛选。详情中可修正归类、通勤边界或排除异常记录，原始轨迹保留。

新建方向需至少四个有效定位点及 150 米轨迹；起终点半径为 20–500 米。上班、下班保留独立实际轨迹，历史 ETA 仍按具体方向参考计算。
请停车后操作。自动识别路线发生在手动开始记录之后。

## 耗时、定位与耗电说明

- **总耗时 = 移动 + 静止 + 未知**。静止可能是拥堵、临停或停车，不能直接理解为红灯等待；定位缺失不算作零速度。
- 首次取得定位的时间受环境和系统影响，没有固定等待时长。隧道、地库、高楼与相邻道路可能影响定位和路线识别；偏离或定位过期时，进度与预计到达会暂时隐藏。
- 自动到达提示需接近终点并持续低速停留至少 30 秒；提示不会直接结束记录，仍需选择保存或删除。预计到达基于自己的历史剩余耗时，不包含实时路况，也不保证精确到秒。
- 记录期间持续使用定位，会增加耗电。定位请求间隔约两秒，实际频率由系统决定；功耗和长时间锁屏连续性仍需在不同设备、系统和实际路线中测量。
- 先使用正常电池设置。若出现中断，再检查该 App 的电池和后台限制。App 当前不持有唤醒锁，也不申请忽略电池优化。
- 如果权限被撤回或进程被终止，重新打开后会将未结束行程标为中断，保留已保存数据，不会自动续录；中断行程不进入有效通勤统计。

## 编译与安装

需要 **JDK 17**、Android Studio 或 Android 命令行 SDK。配置 `JAVA_HOME`，并通过 `ANDROID_HOME` 或 `local.properties` 的 `sdk.dir` 指定 SDK 路径。安装以下 SDK 组件并接受相应许可：

```text
platforms;android-35
build-tools;35.0.0
platform-tools
```

此电脑的项目专用 JDK 17 与 Android SDK 已配置在被 Git 忽略的 `.tooling/`，使用 `./scripts/gradle-local.sh :app:assembleDebug` 即可自动选用；ADB 路径为 `.tooling/android-sdk/platform-tools/adb`。

首次在另一台电脑编译前，先按[双 Mac 签名配置](docs/signing.zh-CN.md)导入共用密钥；项目不会自动生成新的签名。

仓库内 Gradle Wrapper 固定构建版本，无需单独安装 Gradle。在项目根目录执行：

```sh
./gradlew :app:assembleDebug
```

Windows 使用 `gradlew.bat :app:assembleDebug`。首次构建需要联网下载构建工具与依赖，耗时取决于网络和缓存；App 使用时不需要联网。

生成的安装包为 `app/build/outputs/apk/debug/app-debug.apk`。连接手机、开启 USB 调试并允许电脑后安装：

```sh
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

若流式安装失败，可增加 `--no-streaming` 参数。也可将 APK 传到手机，按系统提示允许该来源安装。USB 调试只用于开发安装，不是日常使用所需权限。此命令生成开发签名的 Debug 包。

## 统计与行程详情的展示

统计页使用月度里程总览、时间分配环图、可点选的每趟耗时柱状图和出发/到达节奏卡片。路线总览按所选月份汇总双向里程、天数和次数，下方数字与图表再按方向筛选；没有有效记录时显示空状态。字体放大时指标改为纵向排列。

行程详情使用相同的森林绿总览与分组卡片，展示耗时、里程、速度、移动/静止/未知、停车信息、真实轨迹及同路线历史比较。长按卡片打开带图标和说明的底部操作面板；编辑表单与删除确认也沿用相同配色和圆角。

## 两台 Mac 交替开发与安装

本项目固定使用 `.signing/debug.keystore`。另一台 Mac 同步代码后，需要从本机私下传输这份密钥并导入一次，再正常编译；缺少密钥或证书不符会明确报错，不再自动生成不同的签名。密钥不通过 Git 同步。

```sh
python3 scripts/import-debug-signing.py "$HOME/Downloads/debug.keystore"
./scripts/gradle-local.sh :app:assembleDebug
```

两台 Mac 使用同一共用证书，可保留数据覆盖升级。详细传输、验证与排错见[双 Mac 签名配置](docs/signing.zh-CN.md)。

## 数据与当前边界

轨迹保存在 App 私有存储，不上传、不埋点，也不在日志中输出精确坐标。应用关闭系统云备份与设备迁移备份，不额外提供应用层加密。**卸载或清除应用数据会丢失本地记录；当前尚无导出、导入或云端找回。**

初版提供轨迹示意，没有地图底图、导航、实时路况或红灯识别。长时间锁屏、实际道路准确性与耗电尚需持续验证；已执行的自动化与设备测试见[测试说明](docs/testing.zh-CN.md)。
